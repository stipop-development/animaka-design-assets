## 2. 유저 상태 (`navState`)

`GET /v4.0.1/home14/me/creator-state` 응답에 아래를 **추가**한다. 이미 쓰는 필드는 바꾸지 않는다.

```json
{
  "navState": "none | payer | creator | heavy",
  "slotCard": { "type": "guide | tryFeature | creatorStats | vip | comeback", "...": "타입별 데이터 (아래 표)" },
  "untried": ["video", "manga", "voice", "moodshot", "scene_image", "animaka"],
  "badges": { "perksClaimable": 2, "unreadChats": 3, "uraNew": true, "newEvidence": false }
}
```

### 판정 순서
위에서부터 먼저 맞는 것이 이긴다.

| 상태 | 조건 |
|---|---|
| `heavy` | 최근 30일 결제일 3일 이상, 또는 30일 DMM pt 사용 상위 10% |
| `creator` | 공개 캐릭터 1개 이상 |
| `payer` | DMM pt 사용 1회 이상 (보너스만 쓴 건 제외) |
| `none` | 나머지 (비로그인 포함) |

### slotCard 타입
| type | 대상 | 데이터 | 문구 (ja) |
|---|---|---|---|
| `guide` | none | `{step, total:5, rewardPt:50}` | はじめてガイド n/5 · 推しと5回はなしてみよう · クリアで +50pt |
| `tryFeature` | payer | `{feature, charId, charName, charImg, discount}` | まだ試していない · {charName}で はじめての{動画} 50%OFF |
| `creatorStats` | creator | `{impressions, chatUsers, earnedPt, rank, toTop10}` | 自分のキャラ · 今日 / 表示 · 会話ユーザー · もらったpt / クリエイターランキング {rank}位 → TOP10まであと {n}会話 |
| `vip` | heavy | `{featureKey}` | VIP · 先行公開 · {制作スタジオ}を先に使えます |
| `comeback` | heavy, 3일 미접속 | `{bonusPt}` | おかえり · ボーナス {n}pt |

- **tryFeature의 기능 순서:** `video` → `scene_image` → `manga` → `voice`. `untried` 중 첫 번째를 고른다.
  - `charId`는 최근 대화한 캐릭터다. 없으면 이미지 없는 버전.
- **닫기(X):** 24시간 동안 다음 후보를 보여준다. 기록은 localStorage `nav_slot_dismiss_{type}`.

> guide 단계 판정·보상 지급은 이번 범위가 아니다. 이번에는 단계 숫자를 **현재 첫 체험 미션 진행도**로 대신 쓴다.
> 없으면 none 상태의 slotCard를 v1.4 「初キャラミッション」 카드로 대체해도 된다.

## 5. 대화방 상단바 · 하단 입력바

시안 보드: R1(1:1) · R2(NTR) · R3(그룹) · R4(데스크톱) · R 규칙 · **S 상태 명세**

### 5-1. 상단바 (모바일 높이 56, NTR은 2줄이라 +36)
**프로필 아이콘을 넣지 않는다.** 프로필은 본문 말풍선 옆에 그대로 보인다. 그만큼 이름과 상태 글이 넓어진다.

| 위치 | 1:1 | NTR | 그룹 |
|---|---|---|---|
| 왼쪽 | ← 뒤로 | ← | ← |
| 이름 (15px 굵게) | 캐릭터 이름 | 그녀 이름 | 방 이름 |
| 상태 한 줄 (11px) | 「オンライン · 好感度 Lv.n」 (민트) | 「{그} は{위치} · 帰宅まであと{n}」 (주황 `#fdba74`) | 「{멤버들} と あなた」 (회색) |
| 버튼 | 음성 · 동영상 | 証拠・記録 | メンバー追加 |
| 오른쪽 | DMM pt 미니칩 · ⋯ | 미니칩 · ⋯ | 미니칩 · ⋯ |
| 2줄 | — | 「いまの場面 · {장면}」 칩 + 「ふたりの距離」 게이지(0–100) | — |

- 버튼은 **최대 3개**. 지금 헤더에 있는 나머지(コレクション, グループチャットを作る, 기억, 모델, 신고, 초기화)는 **⋯ 메뉴로 옮긴다.**
- 상태 한 줄 데이터: 1:1은 기존 好感度/관계 레벨, NTR은 기존 NtrHeader의 away·channel·scene 값을 쓴다. **새 API는 필요 없다.** 값이 없으면 줄을 숨긴다.
- **데스크톱 대화방:**
  - 상단바 구성은 같고, 높이는 64다.
  - 좌측바는 **접지 않는다.** 다른 화면과 같은 296px 풀 버전을 그대로 둔다. 현재 위치는 「はなす」 섹션의 해당 메뉴(マイチャット/NTR/グループ)를 선택 상태로 표시.
  - 오른쪽 프로필 패널은 지금 것을 유지하고, slotCard 1장만 추가한다.

### 5-2. 하단 입력바
위에서 아래로:
1. (그룹만) 「話しかける相手」 칩: みんな / 멤버별. 선택하면 흰 배경, 입력 안내 문구는 「{이름}にメッセージ」.
2. **답장 추천 칩 3개** (지금 「優しく話す / からかう / 大胆に攻める」 자리, 같은 데이터).
3. **입력줄:**
   - (NTR만) 行動 버튼 42px 원
   - 입력란 radius 21. 안에 마이크 버튼
   - 전송 42px 원
4. **맨 아래 한 줄 (10.5px):** 왼쪽 「Premium ▾」(모델 선택 시트, 지금 Premium 버튼과 같은 기능) / 오른쪽 「無料のこり n回 · 1回 {비용}pt」

- 지금 입력란 위에 있는 「初めてのキャラ作成ボーナス 無料メッセージ残りn回」 배너는 **맨 아래 한 줄로 합친다** (배너 삭제).
- http 마이크 경고 문구(「このアドレス(http)では…」)는 테스트 서버에서만 보이는 문구라 그대로 둔다.

### 5-3. 상태 전환
| 상황 | 바뀌는 것 |
|---|---|

## 12. 로딩 규칙 (v1.1 추가 · 좌측바·☰ 메뉴부터, 앞으로 모든 화면 공통)
지금 문제: 좌측바가 로딩될 때 항목이 하나씩 끼어들며 순서가 바뀌고 높이가 출렁인다.

1. **틀 먼저, 내용 나중.** 좌측바·☰ 메뉴는 첫 렌더에서 최종 구조(섹션 순서, 항목 수, 각 높이)를 스켈레톤으로 다 그린다. 데이터가 와도 **자리는 그대로, 안의 내용만 바뀐다.**
2. **고정 높이 슬롯.** 아래 구간은 높이를 미리 잡아 둔다.
   - 프로필+pt 블록, slotCard(가이드/추천 카드), 섹션 제목 28px, 메뉴 항목 44px, AIサポート 블록, 하단 설정 줄.
   - slotCard가 없는 상태로 판정되면 그 자리는 **처음부터 렌더하지 않는다** (나중에 끼워 넣거나 빼지 않음). 판정 전엔 스켈레톤으로 자리를 잡고, 없으면 같은 높이에서 접히는 애니메이션 0.2초.
3. **순서는 서버 응답 한 번으로 확정.** navState(creator-state)가 오기 전엔 직전 값(localStorage 캐시)으로 그리고, 없으면 `none` 순서로 그린다. 응답 후 순서가 바뀌어야 하면 한 번에 바꾼다 (항목 하나씩 이동 금지).
4. **배지·숫자·pt는 자리 고정.** pt는 「… pt」 대신 숫자 폭만큼의 스켈레톤 바. 배지는 오른쪽 고정 위치에 페이드인만.
5. **나타나는 방식:** 스켈레톤은 은은한 쉬머(1.2초 반복). 내용은 위에서 아래로 섹션 단위 페이드인 (섹션마다 40ms 차이, 각 150ms). 움직임(translate)은 쓰지 않는다.
6. **이미지(아바타·썸네일):** 크기 고정한 자리 + 배경색으로 먼저 깔고, 로드되면 페이드인.
7. **공통 컴포넌트로 만든다:** `Skeleton`(바·원·카드) + `useStableLayout` 규칙을 `components/ui/`에 두고, 이후 새 화면도 같은 규칙을 따른다 (높이 바뀌며 채워지는 로딩 금지).
8. **확인:** Chrome DevTools Performance의 CLS 0.00 (좌측바·☰ 메뉴 영역).
